# Авторазметка без дообучения: обзор и программа экспериментов

Проверено 21 сентября 2026. Это карта методов для исследования, не заявление о новизне будущей диссертации.

## Опорные методы более ранних лет

- [Weighted Boxes Fusion](https://arxiv.org/abs/1910.13302): полезный ориентир для ансамблирования. Усреднение прямоугольников нельзя молча назвать усреднением сегментации. В LabelBench вместо WBF реализован выбор существующего полигона по согласию, без выдуманной границы.
- [Grounded SAM](https://arxiv.org/abs/2401.14159): композиция разных foundation models для детекции/сегментации, включая автоматическую разметку. Полезен как пример модульного пайплайна, но не гарантирует качество на исторических рукописях.
- [SAM 3: Segment Anything with Concepts](https://arxiv.org/abs/2511.16719): первичная публикация — ноябрь 2025. Не включён в список новых препринтов 2026. Полезен как будущий open-vocabulary baseline; текущий SAM 2 automatic mask generator не является детектором текста.

## Проверяемый исследовательский вопрос

Повышает ли выбор единственного полигона из **фиксированного пула** предобученных моделей точность авторазметки исторических документов относительно лучшей отдельной модели при одинаковом бюджете ручной проверки?

Модели предобучены, поэтому корректная формулировка — «без дообучения на целевом архиве», а не «необученные модели». Исторические RF-DETR/Doc-UFCN могут иметь сходные обучающие данные; отсутствие утечки нужно проверять отдельно по model cards и происхождению архива.

## Протокол

1. **Единица GT:** каждый явный polygon внутри words. Не склеивать free_lines: часть этих групп содержит разные физические строки. 1000 доступных фото, 131642 полигонов; `3.jpg` и `7925.jpg` упомянуты, но отсутствуют. Полнота ручной разметки этим техническим аудитом не доказана.
2. **Разделение:** первоначально стабильный dev/test по страницам. Для диссертационной оценки заменить на разделение по книге/делу/источнику, чтобы соседние страницы не пересекались. Настройка порогов и выбор метода — только dev. Сохранить окончательные списки файлов до оценки test.
3. **Baselines:** каждая модель отдельно; union; polygon NMS; consensus с 2/3/4 независимыми провайдерами; собственные Gaussian/watershed/assignment из notebooks; VLM-отбор. Разные PP-OCRv6 имеют общий предтренинг и не считаются статистически независимыми источниками свидетельств.
4. **Контроль пула:** сравнивать ранжировщики на одинаковых сохранённых предсказаниях. Если добавляются новые маски, выделять это отдельным экспериментом. Иначе нельзя понять, помогли генерация или отбор.
5. **Ablations:** confidence per model; число моделей; IoU fusion; минимум голосов; без confidence / без геометрии / без VLM; случайный выбор и выбор первой модели как отрицательные контроли; native/ONNX с одинаковым preprocessing.
6. **Основные измерения:** micro precision/recall/F1 при polygon IoU 0.50 и отдельно 0.75; TP/FP/FN; средний IoU только совпавших пар; дубликаты как FP. Текущий оценщик — maximum-cardinality matching, затем maximum IoU. Это **не COCO AP** и не confidence-ranked matching COCO.
7. **Для VLM:** доля законченных ответов, доля uncertain, токены и денежная стоимость, ошибки выбора в конфликтных группах. Отдельно считать качество принятых объектов и покрытие; abstention не должен искусственно улучшать показатель без учёта recall.
8. **Статистика:** парное сравнение на одних страницах, bootstrap по документам/книгам, а не по 131642 взаимозависимым объектам. Сначала pilot, затем заранее зафиксированный test. Не выбирать «лучший» метод многократным просмотром test.
9. **Время:** разделять cold start, warm inference, preprocessing/postprocessing, кэш и внешнюю сеть. `elapsed_seconds` провайдера включает загрузку при первом вызове; оно не является чистым GPU kernel time.
10. **Ручная проверка:** слепая выборка FP/FN и спорных GT; менять эталон только отдельной версией с протоколом, не автоматически вслед за VLM.

## Реализовано и что остаётся исследовательской работой

В платформе реализованы dataset import, confidence, фиксируемые эксперименты, union/NMS/consensus, polygon-оценка, импорт JSON собственного метода, GT-overlay и VLM-проверка страницы. Gaussian/watershed/assignment остаются в пользовательских notebooks и подключаются через экспорт annotations; автоматический подбор гиперпараметров и CMF/HSD не объявляются реализованными. Возможный научный вклад — проверенная стратегия арбитража и abstention для неоднородных исторических фрагментов, а не сам факт объединения моделей.
