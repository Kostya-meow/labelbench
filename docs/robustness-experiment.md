# Надёжность полигонов строк: воспроизводимый эксперимент

Протокол 22.09.2026. Цель — выяснить, когда несколько фиксированных детекторов и преобразования входа улучшают авторазметку без дообучения на целевом архиве. Это исследовательский эксперимент, не обещание улучшения и не готовая диссертация.

## Научные основания

| Работа / первоисточник | Идея для задачи | Что реализовано и что не заявляется |
|---|---|---|
| [Warfield, Zou, Wells: STAPLE, IEEE TMI 2004](https://pmc.ncbi.nlm.nih.gov/articles/PMC1283110/), DOI 10.1109/TMI.2004.828354 | Совместно оценивать скрытую сегментацию и надёжность источников | Мотивирует модель «свидетелей». Здесь реализованы прозрачные голоса семейств и устойчивость; EM-STAPLE не реализован и не имитируется названием. Коррелированные детекторы нарушают простые предпосылки независимости. |
| [Solovyev et al.: Weighted Boxes Fusion, Image and Vision Computing 2021](https://arxiv.org/abs/1910.13302), DOI 10.1016/j.imavis.2021.104117 | Использовать несколько кандидатов для уточнения геометрии вместо удаления всех, кроме одного | Работа относится к прямоугольникам. Здесь сравниваются medoid исходных полигонов и голосование площади масок; это не точная реализация WBF. |
| [Bodla et al.: Soft-NMS, ICCV 2017](https://openaccess.thecvf.com/content_ICCV_2017/papers/Bodla_Soft-NMS_--_Improving_ICCV_2017_paper.pdf) | Подавление дублей и изменение ранжирования кандидатов | Базовый polygon NMS реализован; Soft-NMS — опорное сравнение для следующего этапа, не скрытый компонент текущего метода. |
| [Wang et al.: Aleatoric uncertainty estimation with test-time augmentation, Neurocomputing 2019](https://pmc.ncbi.nlm.nih.gov/articles/PMC6783308/), DOI 10.1016/j.neucom.2019.01.103 | Варьировать изображение при инференсе и оценивать разброс сегментаций | Повторяемость обнаружения и IoU границ после обратного геометрического преобразования. Высокая повторяемость может сохраняться у систематической ошибки. |
| [Hendrycks, Dietterich: ImageNet-C/P, ICLR 2019](https://arxiv.org/abs/1903.12261) | Систематическая проверка обычных искажений | Фиксированные детерминированные искажения документов. Это не официальный ImageNet-C, не его уровни severity и не metric mCE. |
| [Cheng et al.: Boundary IoU, CVPR 2021](https://openaccess.thecvf.com/content/CVPR2021/html/Cheng_Boundary_IoU_Improving_Object-Centric_Image_Segmentation_Evaluation_CVPR_2021_paper.html) | Общая площадь недостаточно характеризует точность границ | Boundary F1 и непрерывный аналог IoU внутренних граничных полос. Не выдаются за официальный raster Boundary AP/COCO evaluator. |
| [Ma et al.: Test-time generative augmentation, Medical Image Analysis 109, 2026](https://www.sciencedirect.com/science/article/pii/S1361841525004487), DOI 10.1016/j.media.2025.103902; [код авторов](https://github.com/maxiao0234/TTGA) | Более содержательные варианты TTA с генеративными преобразованиями | Подтверждённая свежая работа. Генерация не включена: она способна изменить буквы/истинную геометрию, что нарушит неизменность GT. Цитируемость здесь не заявляется. |

Основной проверяемый вопрос: улучшает ли согласие **разных семейств**, дополненное устойчивостью к небольшим искажениям, F1 и точность границ по сравнению с лучшей отдельной моделью и простым NMS?

## Данные и ограничения

- 1000 исходных фото обрабатываются; 977 имеют полный валидный полигонный эталон текущего DB-снимка. 23 страницы без части полигонов получают предсказания, но исключаются из всех метрик GT. Пустой список предсказаний после ошибки не подставляется.
- Единица GT — отдельный исходный polygon базы, визуально проверенный на выборке как строка/фрагмент строки внутри колонки. Группы line_id не склеиваются.
- Старый словный dataset.json не используется. Точная версия и SHA256 каждого фото фиксируются до запуска.
- Модели **предобучены**, веса не обновляются. Корректное название: без дообучения на целевом архиве, а не «без обученных моделей». Пересечение архива с исходными обучающими данными разработчиков моделей неизвестно.
- Полный первый прогон — исследовательский. Инженерный пилот использует несколько тех же страниц. Подтверждающее диссертационное сравнение требует отдельного разбиения по книгам/документам и фиксации метода до просмотра test.

## Зафиксированные условия

Основной набор источников: PP-OCRv6 Medium ONNX, RF-DETR Historical ONNX, Doc-UFCN ONNX, Eynollah ONNX. Это четыре семейства детекторов текстовых строк; SAM/COCO-модели общего назначения здесь не заменяют детекторы строк. Варианты PP-OCR учитываются как одно семейство.

Максимальная сторона изображения 2560 px, уменьшение только при необходимости. Один и тот же базовый масштаб для всех источников. Обратная матрица возвращает полигоны в координаты оригинала. Шум имеет воспроизводимый seed из SHA256 фото, seed запуска и вида искажения.

| Вид | Параметр |
|---|---|
| clean | Исходное RGB после общего ограничения размера |
| brightness | ×0,8 |
| contrast | ×0,75 |
| blur | Gaussian radius 0,8 px на входном масштабе |
| noise | Gaussian σ=4 по каналам RGB в шкале 0–255 |
| jpeg | Quality 65, encode/decode в RAM |
| scale | ×0,8 |
| rotate | −1,5° и +1,5°, белые поля с расширением холста без обрезания |

Это 9 видов × 4 модели × 1000 фото = 36 000 предсказаний. Один изменённый PNG существует временно для совместимости API провайдеров, не сохраняется как результат. Маски RLE не дублируются в БД; хранятся сжатые полигонные предсказания и связи происхождения.

## Методы и абляции

1. `model:*`: каждый детектор на clean, без ансамбля.
2. `union`: все clean-кандидаты; дубли считаются FP.
3. `nms`: polygon IoU NMS. Использует исходный confidence, который не калиброван между моделями.
4. `consensus_clean`: один medoid при поддержке минимум двух семейств, без TTA.
5. `tta:*`: отдельная модель с TTA, группировка использует **только её собственные** предсказания, повторяемость минимум 0,6.
6. `joint_medoid`: один реальный кандидат на группу с максимальным средним polygon IoU. Вес каждого семейства одинаков, его повторные наблюдения делят этот вес.
7. `joint_stable`: medoid + минимум два семейства + средняя доля видов с обнаружением ≥0,6.
8. `mask_vote`: при том же фильтре голосование площади; каждый источник получает вес семейства / число его наблюдений. В локальной ROI максимум 512 px по стороне выбирается область с голосом >0,5. Сохраняется крупнейший внешний контур. Это приближение, теряющее мелкие детали/отверстия, и потому отдельная абляция.
9. `trust:0.2/0.4/0.6/0.8`: заранее заданные пороги индекса доверия для risk–coverage.
10. `without:*`: исключить по одному семейству и повторить joint_stable, чтобы увидеть полезность и вред конкретного источника.

Группировка: anchor-based polygon IoU ≥0,45, clean перед искажёнными видами, затем геометрический порядок. Нет транзитивной склейки цепочки соседних строк. Внутри группы — максимум одно наблюдение provider/view. Выбор medoid не сравнивает raw confidence разных сетей.

`trust = agreement × (family_support + stability) / 2`, где support — доля поддержавших семейств, stability — средняя доля видов с обнаружением среди поддержавших семейств. Это **не вероятность правильности**. Корреляция между семействами и устойчивые систематические ошибки остаются ограничениями. Отсутствующий текст, который не нашла ни одна модель, выявляется как FN по GT; ансамбль не «додумывает» его.

## Метрики и статистика

- Основная: micro instance F1 при polygon IoU ≥0,50; отдельно precision, recall, TP/FP/FN.
- Дополнительная: F1 при IoU ≥0,75, IoU совпавших объектов, union-area IoU/Dice, лишняя/пропущенная площадь.
- Границы: точность/полнота покрытой границы с допуском 0,002 диагонали оригинала. Boundary F1 суммируется по matched-парам и штрафуется за unmatched FP/FN. Matched boundary-band IoU показывается отдельно с явным условием совпадения.
- Устойчивость: доля clean-объектов, имеющих совпадение IoU≥0,45 после преобразования; средний лучший IoU, качество против GT каждого provider/view и latency.
- 2000 paired page bootstrap: 95% CI для micro F1 и разницы joint_stable с базовыми методами; mean±SD per-page F1.
- Paired permutation test по страницам, затем Holm correction для семейства сравнений. Страницы одного документа могут зависеть: интервалы **исследовательские**, не доказательство на независимых книгах. Нельзя выбирать победителя только по p-value.
- Технически неполная страница целиком исключается из сравнений методов. Число таких страниц всегда показано. Три подряд неполные страницы останавливают запуск для проверки.

GT поступает в evaluator только после выбора кандидатов. Он не передаётся преобразованиям или fusion. Порогами нельзя управлять по результатам полного test и затем называть результат независимой проверкой.

## Сохранение, просмотр и остановка

- Дашборд: вкладка **Устойчивость**, ссылка `/?robustness=RUN_ID`. Видны шаги, время/ETA, события, ошибки, график методов и таблица преобразований. Страница и выбранный метод показывают original + GT + выбранные полигоны.
- БД: `data/output/robustness/experiments.sqlite`, SQLite WAL, synchronous FULL. Не копируйте одну `.sqlite` при активной записи без WAL; используйте SQLite backup API для согласованной копии.
- На каждый run: `protocol.json`, `worker.log`, логи изолированных моделей. После окончания: `analysis.json`, `page-metrics.csv`, `analysis-report.md`, PNG графики методов/искажений/risk–coverage.
- `POST /api/robustness` — создать; `GET /api/robustness/{id}` — состояние; `POST .../cancel` — остановить после текущего безопасного шага; `POST .../resume` — продолжить без повторения завершённых предсказаний.
- Обновление страницы, закрытие браузера/чата и перезапуск веб-сервера не останавливают отдельный worker. На Windows worker удерживает систему от автоматического сна только на время расчёта (экран может погаснуть), затем снимает запрос. Принудительный сон/выключение ПК останавливает вычисления; после включения можно продолжить из БД. Код/веса при продолжении должны совпадать с протоколом.
- Закрытие чата не нужно для выполнения: worker работает самостоятельно. API-ключи и платные VLM-запросы в этом эксперименте не используются.
